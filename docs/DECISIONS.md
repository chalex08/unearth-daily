## AI tiers (21 Nov 2026)

_Authoring part superseded on 21 Nov 2026 (see "Puzzle authoring moved to Claude Code"); the paid-tier reasoning still governs the runtime judge._ Originally, offline drafting used the Gemini API free tier; the in-game judge uses the paid tier on a separate, billed Google project. Rules in SPEC §5.3.

- **Why:** the Devvit Rules forbid using Reddit data to train or improve AI models, or letting third parties do so. The Gemini free tier lets Google use submitted content to improve its products; the paid tier does not. So Reddit-derived data (answers, the non-pool log, counts, usernames, anything from Redis or the Reddit API) only ever reaches the paid key.
- **Gemini terms, checked 21 Nov 2026** ([Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms), now redirecting to aistudio.google.com/docs/terms, effective 23 Mar 2026):
  - Unpaid Services: Google uses submitted content and responses to improve and develop its products and ML; human reviewers may read inputs and outputs; "do not submit sensitive, confidential, or personal information".
  - Paid Services: Google doesn't use prompts or responses to improve its products; it logs them for a limited time only to detect Prohibited Use Policy violations.
  - Paid means the API is called through a Cloud project with an active billing account. That's per project, hence two separate projects.
  - Apps made available to users in the EEA, Switzerland or the UK may only use Paid Services. The runtime judge is paid, so this holds.
- **Devvit Rules not re-read today:** developers.reddit.com refused automated fetches, so the AI-training restriction and the LLM-approval requirement are recorded as stated in the project brief. Re-check both on the Devvit Rules page by hand before step 11.

## Spec clarifications (made while writing SPEC.md — review)

- Rarity band boundaries: exactly 20% and exactly 5% are Seam; exactly 1% is Vein.
- Layer 10 gets no rarity bonus (the spec only defines it for layers 1–9).
- Input longer than 40 characters after normalising is rejected with no penalty, rather than truncated.
- An offensive answer breaks a pickaxe like any other invalid answer.
- Share text says "1 rare find" (singular), and drops " · " when no pickaxe broke.
- Invalid answers also count as used, so repeating one is ignored rather than breaking a second pickaxe (an answer that fails clues 1..N fails every later layer too).
- Normalising deletes punctuation, so "sweet-potato" becomes "sweetpotato"; pools need aliases for hyphenated forms.
- Puzzle number lives in each puzzle file (`number`), not derived from the date.

## Open questions and risks

1. **Free-text input and showing other players' answers. Resolved 21 Nov:** the Devvit rules say in-app content should limit free expression and that user text should be published with attribution that can be reported. Agreed rule, now SPEC §4.1: others only ever see hand-reviewed pool answers; AI-approved answers still count everywhere but show as "something else"; players always see their own answers; non-pool answers are logged for review.
2. **Journeys need approval and don't fire in playtest.** Receipts return `DENIED_NOT_ALLOWLISTED` until the app is allowlisted, and `DENIED_PLAYTEST` for playtest versions. No request form is documented, so ask the Devvit team (Discord / r/Devvit) now.
3. **HTTP domain approval** takes 1–2 business days and is triggered by the first upload that lists the domain. The README also needs a "Fetch Domains" section. Add the domain on day 1 of step 4.
4. **Terms and Privacy** links go in the app details form in the Developer Portal (there's no `devvit.json` key); they're required because we use fetch and an LLM. Reddit's own policies can't be used.
5. **Data deletion:** the rules require removing a user's data when they delete their account, and recommend expiring user data after 30 days. Per-day run data gets a 30-day TTL; the streak record keeps only the count and last day.
6. **Cron timezone** isn't documented; check the first daily post fires at 00:00 UTC in playtest.
7. **Flair permission:** no extra permission is documented beyond `permissions.reddit`; check it in playtest.
8. **Gemini model ID and JSON mode** (exact model name, `responseMimeType`/schema support): check against Google's docs in step 4.
9. **Direct launch:** a reserved `_direct_launch` entrypoint lets Reddit's Daily Games surfaces open the game straight into expanded mode. It's a nice-to-have for step 10.
10. **LLM approval.** Devvit requires prior approval for LLM use. Until it's granted the game runs without AI (SPEC §4, §5.3). Request it along with Journeys (PLAN "Start now").
11. **Gemini age terms.** The Gemini API terms require users to be 18+ and bar use in an app "likely to be accessed by individuals under the age of 18". Reddit allows users from 13. This applies to both tiers; raise it with the Devvit team in the LLM approval request.

## Puzzle authoring moved to Claude Code (21 Nov 2026)

- **Decision:** puzzles are written by Claude in a Claude Code session with the project skill `/write-puzzle`. The Gemini free-tier scripts (`tools/generate-puzzle.ts`, `tools/critique-puzzle.ts`, `tools/gemini.ts`) and the `GEMINI_FREE_*` variables are removed. Gemini (paid tier, `geminiApiKey`) is used only for in-game answer checking.
- **Why:** the free-tier quota (20 requests/day) covers only a few drafts a day once validator fixes and critic calls count. Claude-authored puzzles are higher quality (the Gemini drafts had long, multi-constraint clues) and need no API spend.
- **Kept:** the deterministic tools: validator, `tools/review.ts`, the `puzzle-files.ts` depth-list expansion and no-op clue check, the fake-count seed. New `tools/draft-puzzle.ts` (`npm run puzzle:taken`, `npm run puzzle:build`) gives the skill its don't-repeat list and builds and checks a draft from a depth list. The CI check that `src/` never mentions `GEMINI_FREE` stays.
- **Critic:** the skill spawns a fresh-context subagent given only the 10 clues (no pools, no intended answer) to look for a second final answer and obvious early answers.
- **Data rule:** no AI tool or session used for content may receive Reddit data; adding answers to pools from the non-pool answer log is manual only (SPEC §5.3).
- The 22–26 Nov drafts in `content/puzzles/drafts/` came from the Gemini pipeline and should be rewritten with the skill.

## Content pipeline (21 Nov 2026; the Gemini parts are superseded above)

- **Offline model:** `gemini-3.8-flash` suggested for `GEMINI_FREE_MODEL` (free tier per the Gemini pricing page; free-tier RPM/RPD are only shown in AI Studio, per project, reset at midnight PT). The model is read from `.env`, so it can change without code.
- **Gemini REST call:** plain `fetch` to `v1beta/models/{model}:streamGenerateContent?alt=sse` with header `x-goog-api-key`, `generationConfig.responseMimeType: "application/json"` + `responseJsonSchema`, and `thinkingConfig.includeThoughts: true`. No SDK dependency. Confirmed by real runs on 21 Nov: a plain `generateContent` call thinks for over 5 minutes and hits Node fetch's 300s idle timeout, so the script streams and drops `thought` parts. Some calls still time out or get 503; the script retries network errors, 429 and 5xx up to 6 times (`retryDelay` if the 429 has one, else exponential backoff).
- **Free-tier quota:** 20 requests/day for `gemini-3.8-flash` (429 message, 21 Nov 2026). Retries that would wait more than 5 minutes stop the script instead.
- **Critic pass:** `tools/critique-puzzle.ts` (also run by the generator) asks the same free model to fix clear-cut issues and list judgement calls in `drafts/<date>.review.md`. No-op clues are also computed locally.
- **Draft format:** the model returns clues plus each answer's depth; `toPuzzle` expands that into per-layer pools, so the "answer at N is valid at 1..N" rule holds by construction.
- **Dev seed:** the `devvit` 0.15.4 CLI has no Redis command and Redis is per install, reachable only from app code (developers.reddit.com blocks automated fetches; checked against the installed types and `devvit --help`). So fake counts are loaded by a moderator menu item, `/internal/menu/seed-fake-counts`, which refuses when `context.appSlug` is the canonical app.
- **Stats keys** (step 4 writes real data to the same keys): `answers:{date}:{layer}` sorted set, canonical → count; `ends:{date}` hash, deepest layer → runs ended.
- **Puzzle files on the server:** bundled with Vite `import.meta.glob` in `src/server/core/puzzles.ts`; verified they appear in `dist/server` and not `dist/client`.
- **Puzzle #14:** dated 2026-11-21 in `content/` (the test fixture keeps 2026-12-05). Its layer-10 clue is now "…that's oval rather than round" (was "The one and only", which adds no constraint); the fixture matches.
