## AI tiers (21 Nov 2026)

_Authoring part superseded on 21 Nov 2026 (see "Puzzle authoring moved to Claude Code"); the paid-tier reasoning still governs the runtime judge._ Originally, offline drafting used the Gemini API free tier; the in-game judge uses the paid tier on a separate, billed Google project. Rules in SPEC §5.3.

- **Why:** the Devvit Rules forbid using Reddit data to train or improve AI models, or letting third parties do so. The Gemini free tier lets Google use submitted content to improve its products; the paid tier does not. So Reddit-derived data (answers, the non-pool log, counts, usernames, anything from Redis or the Reddit API) only ever reaches the paid key.
- **Gemini terms, checked 21 Nov 2026** ([Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms), now redirecting to aistudio.google.com/docs/terms, effective 23 Mar 2026):
  - Unpaid Services: Google uses submitted content and responses to improve and develop its products and ML; human reviewers may read inputs and outputs; "do not submit sensitive, confidential, or personal information".
  - Paid Services: Google doesn't use prompts or responses to improve its products; it logs them for a limited time only to detect Prohibited Use Policy violations.
  - Paid means the API is called through a Cloud project with an active billing account. That's per project, hence two separate projects.
  - Apps made available to users in the EEA, Switzerland or the UK may only use Paid Services. The runtime judge is paid, so this holds.
- **Devvit Rules not re-read today:** developers.reddit.com refused automated fetches, so the AI-training restriction and the LLM-approval requirement are recorded as stated in the project brief. Re-check both on the Devvit Rules page by hand before step 11.

## Spec clarifications (made while writing SPEC.md — review)

- Rarity band boundaries: exactly 20% and exactly 5% are Seam; exactly 1% is Vein.
- Layer 10 gets no rarity bonus (the spec only defines it for layers 1–9).
- Input longer than 40 characters after normalising is rejected with no penalty, rather than truncated.
- An offensive answer breaks a pickaxe like any other invalid answer.
- Share text says "1 rare find" (singular), and drops " · " when no pickaxe broke.
- Invalid answers also count as used, so repeating one is ignored rather than breaking a second pickaxe (an answer that fails clues 1..N fails every later layer too).
- Normalising deletes punctuation, so "sweet-potato" becomes "sweetpotato"; pools need aliases for hyphenated forms.
- Puzzle number lives in each puzzle file (`number`), not derived from the date. _Changed 22 Nov: derived from launch day 2026-11-08; the file's `number` must match (see "Server and AI judge" below)._

## Puzzle authoring moved to Claude Code (21 Nov 2026)

- **Decision:** puzzles are written by Claude in a Claude Code session with the project skill `/write-puzzle`. The Gemini free-tier scripts (`tools/generate-puzzle.ts`, `tools/critique-puzzle.ts`, `tools/gemini.ts`) and the `GEMINI_FREE_*` variables are removed. Gemini (paid tier, `geminiApiKey`) is used only for in-game answer checking.
- **Why:** the free-tier quota (20 requests/day) covers only a few drafts a day once validator fixes and critic calls count. Claude-authored puzzles are higher quality (the Gemini drafts had long, multi-constraint clues) and need no API spend.
- **Kept:** the deterministic tools: validator, `tools/review.ts`, the `puzzle-files.ts` depth-list expansion and no-op clue check, the fake-count seed. New `tools/draft-puzzle.ts` (`npm run puzzle:taken`, `npm run puzzle:build`) gives the skill its don't-repeat list and builds and checks a draft from a depth list. The CI check that `src/` never mentions `GEMINI_FREE` stays.
- **Critic:** the skill spawns a fresh-context subagent given only the 10 clues (no pools, no intended answer) to look for a second final answer and obvious early answers.
- **Data rule:** no AI tool or session used for content may receive Reddit data; adding answers to pools from the non-pool answer log is manual only (SPEC §5.3).
- The 22–26 Nov drafts in `content/puzzles/drafts/` came from the Gemini pipeline and should be rewritten with the skill.

## Content pipeline (21 Nov 2026; the Gemini parts are superseded above)

- **Offline model:** `gemini-3.8-flash` suggested for `GEMINI_FREE_MODEL` (free tier per the Gemini pricing page; free-tier RPM/RPD are only shown in AI Studio, per project, reset at midnight PT). The model is read from `.env`, so it can change without code.
- **Gemini REST call:** plain `fetch` to `v1beta/models/{model}:streamGenerateContent?alt=sse` with header `x-goog-api-key`, `generationConfig.responseMimeType: "application/json"` + `responseJsonSchema`, and `thinkingConfig.includeThoughts: true`. No SDK dependency. Confirmed by real runs on 21 Nov: a plain `generateContent` call thinks for over 5 minutes and hits Node fetch's 300s idle timeout, so the script streams and drops `thought` parts. Some calls still time out or get 503; the script retries network errors, 429 and 5xx up to 6 times (`retryDelay` if the 429 has one, else exponential backoff).
- **Free-tier quota:** 20 requests/day for `gemini-3.8-flash` (429 message, 21 Nov 2026). Retries that would wait more than 5 minutes stop the script instead.
- **Critic pass:** `tools/critique-puzzle.ts` (also run by the generator) asks the same free model to fix clear-cut issues and list judgement calls in `drafts/<date>.review.md`. No-op clues are also computed locally.
- **Draft format:** the model returns clues plus each answer's depth; `toPuzzle` expands that into per-layer pools, so the "answer at N is valid at 1..N" rule holds by construction.
- **Dev seed:** the `devvit` 0.15.4 CLI has no Redis command and Redis is per install, reachable only from app code (developers.reddit.com blocks automated fetches; checked against the installed types and `devvit --help`). So fake counts are loaded by a moderator menu item, `/internal/menu/seed-fake-counts`, which refuses when `context.appSlug` is the canonical app.
- **Stats keys** (step 4 writes real data to the same keys): `answers:{date}:{layer}` sorted set, canonical → count; `ends:{date}` hash, deepest layer → runs ended.
- **Puzzle files on the server:** bundled with Vite `import.meta.glob` in `src/server/core/puzzles.ts`; verified they appear in `dist/server` and not `dist/client`.
- **Puzzle #14:** dated 2026-11-21 in `content/` (the test fixture keeps 2026-12-05). Its layer-10 clue is now "…that's oval rather than round" (was "The one and only", which adds no constraint); the fixture matches.

## Server and AI judge (22 Nov 2026)

- **Puzzle number** comes from a fixed launch day, 2026-11-08 (#1), so 2026-11-21 stays #14. `puzzleNumber()` in `src/shared/game.ts`; a test checks every bundled file's `number` against it.
- **Judge model:** `gemini-3.5-flash-lite` (listed "Stable", "fastest, most cost-effective" on aistudio.google.com/docs/models, 22 Nov). Its default thinking level is "minimal", so no thinking config is sent.
- **Judge call:** `POST v1beta/models/{model}:generateContent` with `x-goog-api-key`, `generationConfig.responseMimeType: "application/json"` + `responseJsonSchema`, `temperature: 0`, `AbortSignal.timeout(8000)`. This is the shape that worked in real runs on 21 Nov. Google's docs moved on 22 Nov to pages written for the new Interactions API (`/v1beta/interactions`, `response_format`) and no longer show these fields, so **confirm the call in playtest**, and switch to Interactions if generateContent stops working. No system instruction field: the whole prompt is one user turn, with the answer JSON-quoted last and marked as data.
- **What the judge gets:** clues 1..N and the normalised answer (letters, digits and spaces, at most 40 characters). Nothing else.
- **No-AI mode:** no `geminiApiKey` → `MockJudge` with no verdicts → every non-pool, uncached answer gets "Couldn't check that, try again". LLM approval not granted or domain not approved → the fetch fails → the same. Failures are never cached and never cost a pickaxe.
- **Permissions:** `permissions.http.domains: ["generativelanguage.googleapis.com"]` and `permissions.redis: true` in `devvit.json`. Checked against the installed config schema (`@devvit/shared-types/schemas/config-file.v1.json` and its defaults code): Redis is inferred per field, so declaring `http` alone wouldn't disable it; it's explicit anyway.
- **Races:** one submit at a time per user via `incrBy` on a lock key (1 = acquired) with a 15s TTL, longer than the 8s judge timeout. Requests carry the layer they answer, so a repeated submit after the first one finished gets 409 instead of a second move. Run creation uses `hSetNX` (returns 1 only for the creator), so the player count can't double.
- **User identity in Redis:** `context.userId` (`t2_…`), never the username.
- **Alias reuse:** if an answer misses the current pool but matches a layer-1 pool entry already used (e.g. "tigers" after "tiger"), it's ignored as reuse instead of going to the judge.
- **Non-pool answer log:** no separate key. It's the members of `answers:{day}:{layer}` that aren't pool canonicals. The moderator menu item to read it is not built yet.
- **Tests:** `@devvit/web/server` is mocked with a small in-memory Redis in `api.test.ts`; Gemini is mocked by stubbing global `fetch`, so the settings → judge → fetch wiring is tested for real.

## Journeys setup (researched 22 Nov 2026)

Sources: the docs repo `reddit/devvit-docs` (`docs/capabilities/analytics/devvit-journeys.md`, `journeys-receipts.md`, `journeys-dashboard.md`; developers.reddit.com refused automated fetches), the published `@devvit/analytics@0.15.4` package, and the installed `@devvit/protos` telemetry types.

- **Eligibility:** the docs say telemetry is Devvit Web only and "restricted by a server-side allowlist. Your app will only emit journey events after it has been approved in the review process." No page, package code or proto says it's enabled automatically for an app type or category (the Direct Launch / Daily Games page doesn't mention Journeys). The developer understands it's enabled for certain kinds of apps, so we don't request it now; the receipts on the uploaded canonical app will tell us.
- **Receipts** (proto `JourneyReceiptStatus`, the source of truth for whether an event was recorded): `VALID`, `DENIED_NOT_ALLOWLISTED` ("the app is not allowlisted"), `DENIED_RATE_LIMITED`, `DENIED_DUPLICATE`, `INVALID`, `DENIED_DISABLED` ("Journey telemetry is disabled"), `DENIED_PLAYTEST` ("the app version is a playtest version"), `UNSPECIFIED`, all prefixed `JOURNEY_RECEIPT_`. So **events never record in playtest**; test receipts on an uploaded version.
- **Config:** `"permissions": { "journeys": true }` in `devvit.json`.
- **Package:** `@devvit/analytics` 0.15.4 (matches our other `@devvit/*` packages). Its README says "Intended for internal use only", but the docs tell apps to import it. Peer dependencies: `@devvit/server` and **`express`**.
- **Client API** (`@devvit/analytics/client/reddit`, `telemetry`): `startJourney()`, `progress({ progress, action?, actionDetails? })` with `progress` 0.0–1.0, `interaction({ action, actionDetails? })`, `endJourney({ complete?, game?: { win, score } })`, `appReady()`, plus `getActiveJourneyId` / `setJourneyId` / `clearJourneyId`. The journey ID is managed by the client. Client events go to `/api/telemetry/journey/...`.
- **Server API** (`@devvit/analytics/server/reddit`): `telemetry` and `createTelemetryRouter()`, which returns an **Express** router for `/api/telemetry`. Our server is Hono, so step 10 either adds a small Hono route at `/api/telemetry/...` that calls the exported `journeyProgressForClient` / `endJourneyForClient`, or ends journeys from our own server routes with `telemetry.endJourney({ journeyId, complete, game })`, using the `x-devvit-journey-id` header the client sends.
- **Rules:** fire on committed user actions (on release, not press); `startJourney` must not record page or app views; no PII in `action` / `actionDetails` (so no usernames or answers). The platform may validate this and delay approval for apps that break it. No numeric rate limit is documented.
- **Plan for UNEARTH:** start the journey on the Play tap, progress `layer/10` on each cleared layer, end with `{ complete, game: { win: cleared, score } }`, and `appReady()` once the game is interactive. No events per answer typed.

## Playable client (22 Nov 2026)

- **Structure:** `game.html` = Phaser canvas (`#world`, scene `World` in `src/client/world.ts`) under a DOM overlay (`#app`: HUD, clue, form, result line, end panel). The template scenes and their assets are gone. The server is unchanged: the client only calls `/api/start`, `/api/answer`, `/api/result`.
- **Phaser 4 camera:** `Scale.RESIZE` resizes the canvas but not the camera viewport, so `World.layout` calls `this.cameras.resize(width, height)` (as the template did). Instant moves use `resetFX()` + `setZoom()` + `centerOn()`; animated ones `zoomTo`/`pan` with `force`. Checked against the installed `phaser.d.ts`.
- **Mobile keyboard:** `#world` and `#app` take their height from `--vh`, set from `visualViewport.height` on its `resize` event (plus `interactive-widget=resizes-content` in the viewport meta), so the input stays above the keyboard on iOS, where the layout viewport doesn't shrink. The camera puts the current stratum 40% down the screen, in the gap between HUD and answer panel.
- **Copy:** `navigator.clipboard.writeText` then `showToast` (from `@devvit/web/client`, checked in the installed types); if the webview blocks the clipboard, the share textarea is selected for a manual copy.
- **Feed view:** `splash.html` is now a plain title + Play button (`requestExpandedMode(e, 'game')`). The real feed view is step 10.

## Visual system (22 Nov 2026)

- **Fonts are bundled, never loaded from a CDN.** The Devvit Web docs (reddit/devvit-docs, `versioned_docs/version-0.15/capabilities/devvit-web/devvit_web_overview.mdx`, read via GitHub because developers.reddit.com refuses automated fetches) say: "You can't have any external requests other than the app's webview domain. All backend responses are locked down to the webview domain via CSP." So Google Fonts can't load in the client. The faces come from npm and Vite bundles the files: `@fontsource-variable/eb-garamond@5.3.0` (roman and italic, variable) and `@fontsource/atkinson-hyperlegible-next@5.3.0` (latin 400 and 700), both SIL OFL 1.1, imported in `src/client/tokens.css`.
- **Phaser text waits for the fonts:** `game.ts` creates the `Phaser.Game` after `document.fonts.load()` settles for both EB Garamond styles, so the rock is never lettered in the fallback face.
- **Strata are drawn in code** (`src/client/strata.ts`): one 512×220 canvas texture per stratum (`textures.createCanvas`), shown as a `TileSprite` across the width. Palette colours are hex because Phaser and canvas both take them. DOM chrome tokens are OKLCH in `tokens.css`, and the current ore reaches CSS as `--ore`, set per element from `STRATA`.
- **Design system:** `docs/DESIGN.md` (palette, type, recess, chain, reveal pacing, fossils, motion, reduced motion).
- **Dev jump:** `jumpRun` in `src/server/routes/seed.ts` rewrites the caller's own run for today with pool answers (bands cycle Common, Seam, Vein through the commonness labels, as on a cold start). Reached from a moderator menu form on dev installs ("Jump to a layer (dev)", select field values are `string[]` per the installed `SelectField` type) and from `game.html?jump=N` in the local preview via `POST /api/dev/jump`. Both refuse unless `context.appSlug` is present and isn't `unearth-daily`, so an unknown context refuses rather than allows. Answer counts, graveyard and streak are untouched.
- **Mineral icons** live in `public/icons/` (copied to the client root by Vite, like the template's `snoo.png`) and are referenced as relative `icons/NN-name.svg`, because the client tsconfig has no `vite/client` types for `import.meta.glob`.
- **Camera aim:** `World.gap()` returns the screen band between the HUD and the visible panel (set from `game.ts`), and both play and the end-screen pull-back centre on it, since the recess grows with the chain.
- **Phaser text resolution:** Phaser 4's game config has no `resolution` (checked in the installed `phaser.d.ts`; only Text styles have one), so lettering sets `resolution: devicePixelRatio` per Text. Rendering the whole canvas at device pixel ratio is a step 7 job.

## The world (step 7, 22 Nov 2026)

- **Canvas at device pixel ratio.** Phaser 4's game config has no `resolution`, so the game uses `Scale.NONE` with `zoom: 1/K` and a size of K × the box (K = min(devicePixelRatio, 2); a DPR of 3 would be 2.25× the fill cost for no visible gain). A `ResizeObserver` on `#world` calls `scale.resize`; the camera zoom is K × the game zoom, so world units stay CSS px. Canvas textures are created at K × their size, and any sprite using one is sized with `setDisplaySize`, never `setScale` (that was the cause of a double-size lamp on K=2 screens during development).
- **Lighting is not Phaser's lights.** One 'lamp' canvas texture (black with a soft hole) plus four solid-colour images in a container, positioned each frame the camera moves; the Uranium glow is additive images above it. Cheaper and more predictable on mobile GPUs than per-pixel lights.
- **Particles:** one emitter of dust motes, `maxAliveParticles: 14`, off under reduced motion. Step 8's debris keeps the same kind of cap.
- **Textures are lazy:** a stratum is drawn when the camera is within 3 layers; the one past that after the camera settles; all for the pull-back.
- **Clue on the rock, text in the DOM.** The carved clue is canvas text; `#clue` stays in the DOM for screen readers and is visually hidden only once the canvas sets `body[data-carved]`. If the world never starts, the DOM clue stays visible.
- **Fossils are objects, not lettering** (SPEC §6.3 says embedded objects; DESIGN §7 updated). `#fossil-list` gives screen readers the same data.
- **Dev tool quirk, not fixed here:** `?jump=11` (end screen) fails on the 22 Nov puzzle with "No unused answer for layer 10", because its layer-10 answer was already picked at layer 9. To reach the end locally, break all three pickaxes instead.

## Step 7 review fixes (22 Nov 2026)

- **Carved clue falls back to the recess** below 170px of rock showing (`MIN_CARVE` in `world.ts`), checked on every layout. Found at 390×440 (keyboard up), where the carved clue was cropped and the DOM copy hidden. Showing the DOM clue only shrinks the gap further, so the switch can't oscillate.
- **Text:** a layout sets each Phaser `Text`'s style and content with `setText` then `TextStyle.setStyle(style, true)` (at most two renders, and `true` is needed: with `false` the font metrics aren't recomputed, so a 14px→21px change laid out with the old line height), skipped entirely when unchanged (each Text setter re-renders its canvas, and the keyboard fires a resize every frame). Fossils redraw only when the width, data, open fossil or pull-back changes. `scale.resize` is debounced 100ms.
- **Textures** for strata not yet reached are drawn one every 250ms while the camera is still, so the end-of-run pull-back no longer draws up to seven in one frame (all 11 at K=2 is ~20 MB of texture).
- **First descent:** the "first placement cuts" counter now counts a `dig` made before the scene exists, so the first strike after a slow font load still slides.
- **Surface opening:** a fresh run (layer 1, nothing cleared) starts on the Surface and sinks to layer 1 (1.6s); resumed runs and reduced motion don't.

## Step 7 second review: correctness, mobile performance, accessibility (22 Nov 2026)

Three focused reviews of the step 7 world. Each claim was checked against the installed Phaser 4.2.1 source before acting. Fixed:

- **Fossil tap area** is in the frame's own pixels (`InputManager.pointWithinHitArea` adds `displayOriginX/Y`), and canvas textures are K× (`canvas()`), so the hit circle is `Circle(32K, 32K, …)`. It was a quarter-size circle off-centre on every K=2 phone.
- **Resizes keep animations running.** Phaser fires its scale `resize` from its own window listener too (and `ScaleManager.refresh` emits even at the same size), so the handler now retargets a running move (`layout(this.animating())`) instead of snapping it. The Surface opening is held by `layout()` itself while its timer waits, so a resize can't cut it, and the timer reads the current size when it fires.
- **Panels re-measure the gap:** a ResizeObserver on `#hud`, `#play` and `#end` calls `world.relayout()`, which re-aims only if the gap changed.
- **Opening only for fresh runs:** `game.ts` passes it (nothing cleared and no pickaxe broken), not inferred from layer 1.
- **Frame rate:** `fps: { limit: 60 }` in the game config, and `game.loop.setFPSLimit(30)` whenever no camera or light tween runs (`TimeStep.setFPSLimit`, Phaser 4.2.0+). `render.antialiasGL: false`.
- **Load:** only layers ±1 draw before first paint; idle prefetch does the rest. Text re-renders once for a text-only or style-only change. `setFossils` skips identical stats.
- **Fossils above the darkness**, fainter (DESIGN §7). Computed contrast under the darkness had been 1.0–2.9:1.
- **Screen readers:** `#clue` and `#reveal` lost `aria-live` (changes inside `display:none` aren't announced); one always-rendered `#announce` (`role="status"`) says each strike and each new clue. `#answer` is described by the layer line and clue. `#chain` and `#fossil-list` are focusable scroll boxes (Safari doesn't make scroll containers focusable).
- **Short screens:** `#play` is a flex column with `min-height: 0` and the chain shrinks, so the input stays above the keyboard on small and landscape phones.
- **Clue placement** also checks the clue's own height and scale (DESIGN §12); forced colours / more contrast always use the DOM clue; `visualViewport` `scroll` also runs `fit()` (iOS keyboard panning).

Not changed, on purpose:

- **Texture memory** is estimated at ~80 MB on a K=2 phone once every stratum is drawn: Phaser's `CanvasTexture` keeps an `imageData` copy of each canvas besides the canvas and the GL texture. Avoiding it means registering a plain canvas through `textures.addImage`, whose type only takes `HTMLImageElement`, i.e. a type cast, which AGENTS.md forbids. Revisit if the Reddit app's webview is seen being killed (profile first).
- **K = min(DPR, 1.5)** would cut GPU fill ~44% at some loss of sharpness, and dropping the warm lamp glow ~0.7 screen of fill: both design calls, left until a profile on a real mid-range Android phone says they're needed.
- **Dust motes run continuously** (WCAG 2.2.2 pause control): decorative, faint, and off under reduced motion; no pause control added.

## Step 8: the feel (22 Nov 2026)

- **Howler.js `2.2.4`** (the current release; last published Sep 2023, so no upstream fixes are coming) with `@types/howler@2.2.13`, both pinned. Sounds are Web Audio, fetched same-origin from `sounds/*.wav`, which the Devvit CSP should allow (only external requests are blocked). Not yet confirmed inside the Reddit webview; check in playtest.
- **Sounds are original.** `tools/make-sounds.ts` synthesises five mono 16-bit WAVs into `public/sounds/` (strike, clink, descend, chime, hum; 118 KB in all), released CC0. Re-run `node tools/make-sounds.ts` to regenerate. Chosen over downloaded samples so nothing needs a licence check or a download.
- **Mute** is a HUD button (`aria-pressed` = muted), remembered in `localStorage` (`unearth.muted`; storage failures fall back to session-only). `Howler.mute` is also on while the tab is hidden (PLAN step 8).
- **Uranium hum** loops while the player is on layer 10 and fades out when the run ends. Howler queues it until the first tap unlocks audio, so a resumed run at layer 10 starts humming after the first interaction.
- **Pacing changed from DESIGN §5:** Seam, Vein and Mother Lode no longer all hold 2.5s. Holds are now 1.0 / 1.5 / 2.0 / 2.5s (Common / Seam / Vein / Mother Lode and Uranium), counted from the strike, so rarer bands linger slightly longer. A tap or Enter still skips. Timings live in `src/client/feel.ts` (tested) and DESIGN §13.
- **A wrong answer never blocks typing.** The input is never disabled for one, so the 420ms bounce (`WRONG_MS`, asserted under 600 in `feel.test.ts`) plays while you can already type.
- **Haptics** use `navigator.vibrate` where it exists (Android webviews, not iOS) and are skipped under reduced motion.
- **The in-world score label duplicates the recess reveal on purpose:** the label is the brief SPEC §6.4 transient on the rock; the recess reveal stays for reading and for screen readers (DESIGN §5).
- Ore marks stay in the rock for the run and are not re-laid out if the canvas width changes mid-run (a `shortcut:` comment in `world.ts`).
